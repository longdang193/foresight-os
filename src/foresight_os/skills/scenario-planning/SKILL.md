# Scenario Planning

## Inputs
Use the decision, horizon, scope, baseline evidence, constraints, uncertain drivers, available options, and assumptions. Make missing inputs explicit and proceed with a bounded provisional frame when useful.

## When to use
Use when material uncertainty in demand, technology, competition, regulation,
or implementation could change the decision over its horizon.

## Do not use / route instead
Do not use scenarios as forecasts, probability claims, or a substitute for
missing baseline evidence. Route assumption testing to `key-assumptions-check`,
numerical comparisons to `quantitative-sanity-check`, and unresolved gaps to
`abstain-or-escalate`.

## Workflow
1. Separate observed conditions, relatively persistent trends, and critical uncertainties. Evaluate the organization, customers, competitors, and external environment to the depth needed for this decision.
2. Select two or three decision-sensitive uncertainties. Build a small set of distinct plausible futures, normally three; do not force a two-axis matrix when it creates artificial combinations.
3. Describe each scenario's causal sequence, assumptions, interactions, and horizon. Check internal consistency and resource constraints. Label hypothetical quantities; do not turn scenarios into predictions or invented probabilities.
4. Compare the same strategic options across scenarios using consistent measures. Reuse deterministic calculations. Distinguish robust actions, reversible experiments, and commitments conditional on particular assumptions.
5. Challenge the preferred option with an adverse but plausible scenario. Identify evidence that would weaken the scenario itself and conditions that would reverse the recommendation.
6. Define signposts: indicator, baseline/source, threshold/event, observation window, and response. Specify the next monitoring or research action without creating an always-on scheduler.

## Output
Return a scenario comparison with drivers, assumptions, evidence IDs, implications, option performance, robust actions, conditional recommendations, and signposts. Preserve unsupported assumptions and unresolved questions in the derived finding/report.

## Completion check
Each scenario must alter a meaningful choice or exposure. If all scenarios imply the same action, explain its robustness. Without quantitative evidence, use an explicit qualitative comparison rather than fabricated chart data.

## Pair with
- `key-assumptions-check` for driver assumptions and disconfirmation conditions.
- `quantitative-sanity-check` for consistent option measures.
- `presentation-storytelling` for a decision-focused scenario narrative.

## Anti-patterns
- Naming cosmetic variants as distinct futures.
- Assigning invented probabilities or treating a scenario as a prediction.
- Creating signposts without a threshold, observation window, or response.
